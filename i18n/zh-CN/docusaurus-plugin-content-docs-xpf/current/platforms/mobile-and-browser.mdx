## 前提条件

在添加移动端或浏览器目标之前，请确保你的项目已经可以在桌面端上运行 XPF，并且 XPF SDK 已正确配置。如果你还没有完成这些，请参阅 [入门指南](/xpf/getting-started)。

:::tip
[CalculatorDemo 仓库](https://github.com/AvaloniaUIOU/CalculatorDemo) 包含一个在所有平台上都可运行的 XPF 示例。如有需要，请向支持团队申请访问权限。
:::

你还需要为每个目标平台准备开发机器。这些步骤与所有 .NET 移动端和浏览器项目通用：

- [配置 Android 开发环境](/docs/platform-specific-guides/android)
- [配置 iOS 开发环境](/docs/platform-specific-guides/ios)
- [配置浏览器开发环境](/docs/platform-specific-guides/webassembly)

## 多目标编译

.NET 中对移动端和浏览器的支持依赖于平台特定的 workload 和目标框架。桌面应用程序通常使用 `net8.0` 或 `net8.0-windows`，它们也可以通过 XPF SDK 兼容层在 Linux 和 macOS 上运行。

要支持 Android、iOS 或浏览器，你的项目需要相应的目标框架：`net8.0-android`、`net8.0-ios` 和 `net8.0-browser`。

如果你熟悉 Avalonia 的跨平台模板，可能知道 Avalonia 建议为每个目标创建独立项目。但对于 XPF 项目，**不建议**这样做。WPF 的嵌入式资源系统假定可执行项目是包含所有资源的主项目，将其拆分为多个项目会破坏这一点。

相反，通过修改你的 `.csproj`，使用单个多目标项目：

```diff
-        <TargetFramework>net8.0-windows</TargetFramework>
+        <TargetFrameworks>net8.0;net8.0-ios;net8.0-android;net8.0-browser</TargetFrameworks>
```

其中 `net8.0` 会被所有桌面平台复用。

另外，在 XPF SDK 中启用多目标编译支持：

```diff
+        <XpfSingleProject>true</XpfSingleProject>
```

:::caution
仅在**可执行项目**上添加 `net8.0-android`、`net8.0-ios` 和 `net8.0-browser` 目标框架。不要将它们添加到共享库项目中。尤其是，`net8.0-browser` 不支持非可执行项目，并会导致诸如“Program does not contain a static 'Main' method suitable for an entry point.”之类的构建错误。

库项目应以 `net8.0` 为目标。如果需要，也可以在库项目上使用 XPF SDK。如果某个库需要访问原生移动端 API，你可以添加 `net8.0-android` 或 `net8.0-ios`，但不能添加 `net8.0-browser`。
:::

## 定义入口点

桌面 WPF 应用程序以 `Main` 方法启动，但移动端和浏览器平台有不同的入口点机制。Android 需要一个根 `Activity`，iOS 需要一个 `AppDelegate`，而浏览器应用则由网页本身启动。

为此，请在你的 `Application` 类中定义一个共享入口点，让每个平台都可以调用：

```diff
    public partial class App : Application
    {
+        /// Shared App entry point.
+        public static int Start()
+        {
+            var app = new App();
+            app.InitializeComponent();
+
+            // Note, this method returns early on Mobile and Browser.
+            return app.Run();
+        }
    }
```

## 构建

### .NET CLI

一次构建所有平台：

```bash
dotnet build
```

构建特定平台：

```bash
dotnet build -f net8.0-android
```

运行浏览器目标：

```bash
dotnet run -f net8.0-browser
```

:::note
.NET 官方并不支持直接通过 CLI 运行 Android 或 iOS 应用。对于这些目标，请使用 IDE。
:::

### Visual Studio

默认情况下，Visual Studio 以桌面框架（`net8.0`）为目标。要选择其他平台，请使用目标框架下拉菜单：

![VS 目标选择器](/img/running-on-mobile-and-browser/vs-target-selector.png)

当选择 Android 时，Visual Studio 会显示用于模拟器或已连接设备的选择器：

![VS Android 模拟器选择器](/img/running-on-mobile-and-browser/vs-android-emulators-selector.png)

如果没有显示任何模拟器，请确认：
- 已安装 Android SDK（可在 Visual Studio Installer 的“Individual Components”中安装）
- 至少已配置一个 Android 模拟器（打开 **Tools > Android > Android Device Manager** 创建一个）
- Visual Studio 和 XPF SDK 都已更新到最新版本

### JetBrains Rider

Rider 的工作方式与 Visual Studio 类似。请从运行配置下拉菜单中选择你的目标框架：

![Rider 目标选择器](/img/running-on-mobile-and-browser/rider-target-selector.png)

默认情况下不会显示 Browser 目标。要添加它，请在下拉菜单中点击 **Edit Configurations**，然后添加一个新的 “.NET Project” 配置，并选择正确的目标框架。Rider 会自动填充其余字段。

![Rider 添加浏览器目标](/img/running-on-mobile-and-browser/rider-adding-browser-target.png)

### VS Code

VS Code 可通过 [C# Dev Kit](https://marketplace.visualstudio.com/items?itemName=ms-dotnettools.csdevkit) 和 [.NET MAUI](https://marketplace.visualstudio.com/items?itemName=ms-dotnettools.dotnet-maui) 扩展支持移动端目标。

:::note
Apple 不允许在非 macOS 机器上使用 iOS 模拟器或连接的 iOS 设备。Apple 移动端目标请使用 macOS，或者尝试 [Visual Studio 的 macOS 配对功能](https://learn.microsoft.com/en-us/dotnet/maui/ios/pair-to-mac?view=net-maui-8.0)。
:::

## 发布

使用 .NET CLI 进行发布：

```bash
# 在 /bin/Release/net8.0-android/publish/ 中输出 APK
dotnet publish -f net8.0-android

# 在 /bin/Release/net8.0-ios/publish/ 中输出 IPA
dotnet publish -f net8.0-ios

# 在 /bin/Release/net8.0-browser/browser-wasm/AppBundle/ 中输出应用包
dotnet publish -f net8.0-browser
```

:::caution
由于裁剪和 AOT 编译，Release 配置下的发布在移动端和浏览器项目中存在已知问题。请充分测试你发布后的输出。
:::

## 已知限制

与桌面端相比，浏览器和移动端平台本身存在一些限制。XPF 为其中部分限制提供了兼容层，但另一些则需要你修改应用程序代码。

### 窗口管理

XPF 通过嵌入在平台单视图中的虚拟桌面（移动应用视图或网页内容）在移动端和浏览器目标上支持 `Window` 类。启用此功能无需额外代码。

虚拟窗口的当前限制：
- 暂不支持调整大小和拖动
- 不会渲染窗口装饰
- 暂不支持拥有者窗口（但 `ShowDialog` 可用）

让主窗口最大化，使其在移动端和浏览器上填满整个屏幕：

```csharp
public MainWindow()
{
    InitializeComponent();

    if (OperatingSystem.IsBrowser() || OperatingSystem.IsAndroid() || OperatingSystem.IsIOS())
    {
        WindowState = WindowState.Maximized;
    }
}
```

### DispatcherFrame

`DispatcherFrame` 以及相关的 `Dispatcher` API 在任何移动端或浏览器平台上都不受支持。

### 同步对话框 API

WPF 的同步对话框 API（`Window.ShowDialog()`、`MessageBox.Show()`）可以在桌面端工作，但无法在移动端和浏览器上支持，因为这些平台不能阻塞主线程。

请改用异步扩展方法：

**MessageBox：**
```diff
-var result = MessageBox.Show(parent, "Operation cannot be performed", "Title", MessageBoxButton.OK);
+var result = await MessageBoxEx.ShowAsync(parent, "Operation cannot be performed", "Title", MessageBoxButton.OK);
```

**ShowDialog：**
```diff
var dialog = new Window();
dialog.Owner = this;
-var result = dialog.ShowDialog();
+var result = await dialog.ShowDialogAsync();
```

这些扩展方法在桌面目标上也同样可用，因此你可以在所有地方使用它们以保持一致性。

:::note
文件对话框的异步扩展方法目前尚不可用，但已在计划中。如果你在移动端或浏览器上需要这些或其他 API，请联系支持团队。
:::

### 文件系统访问

移动端和浏览器应用处于沙盒环境中。无法通过路径直接访问文件系统。

请将文件 API 的使用限制在文件选择器和基于流的 API。要在移动端访问可写的应用数据文件夹：

```csharp
var appDataPath = Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData);
```

:::note
浏览器应用除了用户主动发起的文件对话框之外，无法访问文件系统。
:::

### 浏览器中的线程

浏览器环境对线程的支持非常有限。应将其视为一个异步不是可选项而是必需项的环境，因为网页应用的主线程不能被阻塞。

要启用最小线程支持（例如 `Task.Run` 或 `new Thread()`），请在项目文件中添加以下内容：

```xml
<PropertyGroup>
  <WasmEnableThreads>true</WasmEnableThreads>
</PropertyGroup>
```

### 平台特定代码

如果你需要从 XPF 项目中访问平台特定 API，做法与 Avalonia 应用程序相同。详情请参阅 [平台特定 .NET](/docs/platform-specific-guides/dotnet)。
